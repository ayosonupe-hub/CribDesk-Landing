# CribDesk waitlist landing page

Next.js + TypeScript landing page based on the CribDesk design. Signup, live counts, invite attribution, and the confirmation page use the existing [CribDesk Waitlist API](https://cribdesk.vercel.app/docs).

## Run locally

```bash
npm install
cp .env.example .env.local
npm run dev
```

Open http://localhost:3000. **Submitting a form uses the configured backend and can create a real signup and send its welcome email.** The old local JSON database and Upstash integration are no longer used. No login credentials or API keys are needed.

## Configuration

- `WAITLIST_API_URL`: backend origin, default `https://cribdesk.vercel.app`. Server-only; requests are restricted to the documented `/api/v1/waitlist` endpoints.
- `NEXT_PUBLIC_SITE_URL`: landing page's public origin for metadata and sitemap; default `https://cribdesk.ai`.

The browser calls the landing page's `/api/waitlist` server route because the upstream responses currently lack CORS headers. The bridge unwraps the API envelope, preserves errors (including 429 and Retry-After), and never stores signups itself. Before public launch, confirm the backend's per-IP limiter supports this server-to-server path; otherwise proxy traffic may share a rate-limit bucket. Do not trust arbitrary client-supplied IP headers as a workaround.

## Waitlist flow

- Both signup forms send `email`, a hidden `website` honeypot, `source: landing-page`, the optional inviter `ref`, and any standard UTM query parameters.
- The API handles duplicate emails and referral credits. New signups return 201; existing signups return 200 and retain their code.
- `/early/[code]` is the waitlist invite landing page. `/join/[code]` remains a compatibility alias for earlier landing links. `?ref=CODE` is also supported.
- `/joined?code=CODE` reads the member's position, invite count, boost, rewards, and unlocked milestones from the API.
- Share buttons use the API's `shareUrl` and `shareMessage`. Configure the backend's share-link origin to the deployed landing domain; setting `NEXT_PUBLIC_SITE_URL` here does not change links generated by the backend.
- Position is the API's personal referral score, not a globally unique queue rank.

## Deploy to Vercel

1. Select the team's landing-page project, separate from the `cribdesk` API project.
2. Connect a GitHub repository the team can deploy, or deploy this folder with Vercel CLI.
3. Set the two environment variables above for Preview and Production.
4. Deploy a preview, verify the form flow with an approved test email, and confirm the backend share links reach this landing page.
5. Connect the intended public domain and deploy production.

No additional Redis database or email provider is needed in this project; those responsibilities belong to the existing API.
